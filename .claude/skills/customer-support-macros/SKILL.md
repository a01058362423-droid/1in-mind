# 고객 응대 문구 작성

혼자 운영하는 서비스에서 반복되는 고객 문의에 빠르게, 그러나 진심 있게 답할 수 있는 템플릿을 만든다.

## 응대 유형별 원칙

- **버그 리포트**: 먼저 불편에 공감 → 재현 시도/원인 파악 여부 → 예상 해결 시점(모르면 모른다고, 언제까지 업데이트하겠다고 명시) → 감사 인사. 변명이나 과도한 기술적 해명은 피한다.
- **환불 요청**: 거절보다 이유 파악을 우선. 정책이 있다면 명확히 안내하되 딱딱하지 않게. 1인 기업은 유연한 대응이 신뢰를 만든다는 점을 반영해 예외 처리 여지를 열어둔다.
- **기능 요청**: 요청을 진지하게 받아들였다는 신호 먼저, 로드맵에 없으면 솔직히 말하되 왜 우선순위에서 밀렸는지 간단히. "검토하겠습니다" 같은 형식적 답변은 피한다.
- **불만/컴플레인**: 방어적으로 반응하지 않는다. 사실 확인 → 사과(필요시) → 구체적 조치 순. 감정적 표현에 감정적으로 대응하지 않는다.

## 출력 형식

요청받은 상황에 맞는 답변 2가지 버전(간결한 버전 / 조금 더 정중하고 긴 버전)을 제시한다. 실제 고객 이름/상황이 주어지면 그대로 반영하고, 없으면 [고객명], [문제 상황] 같은 플레이스홀더를 쓴다. FAQ 요청 시에는 질문-답변 쌍을 마크다운 리스트로 정리한다.
