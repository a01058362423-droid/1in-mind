# 제품/기능 스펙 작성 (경량 PRD)

1인 개발자가 혼자 구현할 것을 전제로, 관료적이지 않은 실용적 스펙을 작성한다. 목적은 "무엇을 만들지"와 "무엇을 만들지 않을지"를 명확히 하여 스코프가 슬금슬금 커지는 것을 막는 것이다.

## 구성 요소

1. **문제/배경**: 이 기능/제품이 왜 필요한지 1~2문장.
2. **대상 사용자**: 누구를 위한 것인지.
3. **성공 기준**: 이 기능이 배포된 후 무엇을 보면 성공이라 판단할지 (측정 가능한 지표 또는 명확한 사용자 행동).
4. **범위(In Scope)**: 이번 버전에 반드시 포함될 것.
5. **범위 제외(Out of Scope)**: 명시적으로 하지 않을 것. (가장 중요한 섹션 — 나중에 스코프 크립을 막는 근거가 된다.)
6. **핵심 플로우**: 사용자가 이 기능을 쓰는 주요 시나리오를 단계별로. 예외 케이스(에러, 빈 상태, 권한 없음 등)도 최소 1개 이상 포함.
7. **오픈 퀘스천**: 아직 결정 안 된 것, 구현하면서 판단해야 할 것.

## 원칙

- 불확실한 부분은 추측해서 채우지 말고 [확인 필요]로 표시한다.
- "나중에 확장 가능하게"라는 이유로 범위를 넓히지 않는다 — 지금 필요한 것만 In Scope에 넣는다.
- 사용자가 기능을 짧게만 설명해도, 위 7개 항목을 채우기 위해 필요한 질문을 먼저 던지고 답을 받은 뒤 스펙을 작성한다.
