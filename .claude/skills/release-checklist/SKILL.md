# 출시/배포 전 체크리스트

혼자 운영하는 서비스가 런칭 후 감당 못 할 사고(보안 사고, 결제 오류, 법적 문제)를 미리 막기 위한 체크리스트. 프로젝트 성격(웹앱/모바일앱/API 등)에 맞게 항목을 조정해서 제시한다.

## 점검 카테고리

1. **보안 기본**: 환경변수/시크릿이 코드에 하드코딩되지 않았는지, 인증/인가가 실제로 막아야 할 것을 막는지, HTTPS 강제 여부, 의존성 취약점 스캔 여부.
2. **데이터 안전**: 백업 존재 여부와 복구 테스트 여부, 사용자 데이터 삭제/이전 요청 처리 방법.
3. **결제(해당 시)**: 결제 실패/중복 결제 처리, 환불 플로우, 영수증/현금영수증 발급, 테스트 결제로 실제 검증했는지.
4. **법적/정책 최소 요건**: 개인정보처리방침, 이용약관 존재 여부, (한국 서비스라면) 통신판매업 신고 필요 여부 등 — 법률 자문 대체가 아니라 "확인이 필요한 항목"으로 표시.
5. **모니터링**: 에러 발생 시 알림을 받을 수 있는지(로그/알림 채널), 서비스 다운을 감지할 방법.
6. **사용자 경험 안전망**: 빈 상태(데이터 없음), 네트워크 오류, 권한 없음 등 예외 상황에서 앱이 깨지지 않는지.
7. **되돌리기(rollback) 계획**: 배포 후 심각한 문제 발견 시 몇 분 안에 이전 버전으로 되돌릴 수 있는지.

## 출력 형식

프로젝트 맥락에 맞춰 체크박스 리스트(`- [ ]`)로 제시하고, 이 프로젝트에서 특히 위험도가 높아 보이는 항목은 앞쪽에 배치하며 이유를 짧게 덧붙인다. 확인 불가능한 항목(법적 요건 등)은 추측하지 않고 "직접 확인 필요"로 명시한다.
